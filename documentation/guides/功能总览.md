## G. 完整狗头军师 Skill 接入【新增】

| 端 | 开关 | 实现 |
| --- | --- | --- |
| Mac | `GOUTOU_SKILL_MODE=builtin\|full` | `core.skill_mode()` / `skill_root()` / `load_bundle()`；`full` 追加桌面运行时适配说明与 OCR 指南 |
| Android | 设置 → 分析 →「使用完整狗头军师 Skill」（默认关） | `SkillBundle.kt` 读 `assets/goutou_skill/`；每轮注入核心章节 + 2–3 份场景指南，上限 6000 字 |
| 资源 | — | 51 个 asset：`SKILL.md` + 20 `kNN.md` + 23 `pNN.md` + 5 别名 + `guide_ocr.md` + `index.json` |
| 生成器 | — | `scripts/sync_android_skill.py`（幂等），`scripts/validate_skill.py` 跳过扁平化资源 |
| 打包 | — | `scripts/package_mac.py` 的 `DIRS` 加入 `skills/` |
| 运行时边界 | — | `DESKTOP_RUNTIME_NOTE` / `MOBILE_NOTE` 说明上游「不联网 / 不写文件」描述的是 Skill 自身，不是外层 App |

**设计取舍**：不覆盖根目录桌面定制版；不把长中文规则塞进 Jev 英文判断题面；默认关闭，避免每轮 token 暴涨。

## H. 悬浮球稳定性【修复 / 新增】

| 问题 | 修复 |
| --- | --- |
| QQ 等已适配应用 `extract()` 返回 null 时直接 `return`，球既不显示也不报错 | `shouldParkIdleBubble()` + `parkIdleBubble()`：窗口切换、`extract()==null`、识别出聊天窗口但无正文，三处补 idle 球 |
| 节点树拿不到时无法判断前景应用 | 用 `event.packageName` 兜底，但只用于补球，不用于 hide / cancel（IME 可能是事件源） |
| 会话白名单不匹配会主动隐藏球 | 常驻模式下只跳过分析、不收球 |
| 桌面 / 系统 UI / 自己页面收球是按需隐藏设计 | 常驻开关可绕过；总开关关闭与服务销毁的 hide 特意保留 |

## I. OCR 说话人归属【修复】

| 问题 | 修复 |
| --- | --- |
| 本地整屏 OCR 把所有行硬编码成 `Msg("other", ...)`（`OCR_NOTE` 原文「OCR 未分边」） | `ocrLineIsMine(left, right, screenWidth)` 按左右头像留白保守分边；每组只用首行判方向 |
| 视觉模型 prompt 没说明怎么分左右 | 明确「靠右 / 头像在右 = 我，靠左 = 对方，群聊其他人一律对方，分不清写对方」，并要求忽略时间戳 / 昵称 / 输入框 / 回执 |
| 长气泡横跨大半屏可能误判 | **刻意保守**：仍归「对方」，由核对页人工改；绝不把对方的话错算成自己的 |

## K. 明确不支持 / 仍需实机验证

- **Android 微信截图是实验性功能、默认关**：需「设置 → 分析 → 允许微信截图」，只走系统截屏授权 + 整屏本地 OCR，不自动读控件树；支付 / 收款码等 FLAG_SECURE 页面仍拿不到画面。详见 [完整使用教程 4.8](./完整使用教程.md)。
- Windows QQ 群聊与独立聊天窗口暂不支持；填入无法读回验证输入控件。
- iOS 键盘无法自动核实收件人。
- 各端均为预览版，设备与聊天应用兼容性需分别验证；离线检查与 CI 不能替代真机测试。
- 视觉模型路径依赖所选模型是否真的支持图片输入。

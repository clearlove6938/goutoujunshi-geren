1准备本地仓库（二选一）

路径 A（推荐，本机直接做）：不用还原，改动就在现成目录里。打开终端进到该目录，确认提交和 remote 状态：

cd goutoujunshi-jev-chat
git log --oneline -1
git remote -v
git remote -v 无输出 = 本机仓库没有 remote，第 3 步用 remote add。

路径 B（换一台电脑时）：拷走 bundle 再还原，此时 origin 已存在：

git clone -b main goutoujunshi-jev-chat.bundle goutoujunshi-jev-chat
cd goutoujunshi-jev-chat
git log --oneline -1
git remote -v
图 1 · 看到 1bc4980 就说明改动全在
本地目录和 bundle 里都已经包含 skills/goutoujunshi/（63 个文件）和 Android 的 assets/goutou_skill/（51 个文件），不需要再单独同步。
容易踩的坑（取决于你走哪条路径）：从 bundle 执行 git clone 后，origin 会自动指向那个 .bundle 文件，这时用 remote add 会报 remote origin already exists.；但本机现成目录没有 remote，反而必须用 remote add。第 3 步给了两条路径都通用的写法。

2在 GitHub 新建空仓库

本步已完成，可以跳过：你已经建好了空仓库 clearlove6938/goutoujunshi-geren（Quick setup 页、Public、三个初始化项都没勾）。在这个页面只需要点 HTTPS 地址行最右侧的「复制」小图标，拿到 https://github.com/clearlove6938/goutoujunshi-geren.git。页面下半部分 GitHub 自动给的两段命令不要照抄，见第 3 步。

如果以后要另建一个：打开 https://github.com/new，公开或私有都行。

界面上点哪里：新版首页右上角「Type / to search」搜索框右边那个 ＋ ▼ → 下拉选 New repository。注意中间「Ask anything」输入框下面那排也有个 ＋，那是 AI 提问加上下文用的，别点错；左侧「Top repositories」旁的放大镜只是搜仓库。
更省事的做法：直接在浏览器地址栏敲 github.com/new 回车，不用找按钮。
三个勾都不要选：Add a README、Add .gitignore、Choose a license。空仓库才能直接 push -u origin main，否则会先要处理冲突。

3推送

在本机终端执行。第一行是两种路径通用的写法：没有 origin 就新建，已有（指向 bundle）就改地址，不会报 already exists。

git remote add origin https://github.com/clearlove6938/goutoujunshi-geren.git 2>/dev/null || git remote set-url origin https://github.com/clearlove6938/goutoujunshi-geren.git
git remote -v
git push -u origin main
不要照抄 GitHub 空仓库页面给的命令。它写的是 git remote add origin … + git branch -M main：branch -M 对我们多余（已经是 main），而 remote add 只对「本机无 remote」成立；从 bundle clone 出来的仓库会报错。
首次 push 会由 Git Credential Manager 弹浏览器要求 GitHub 授权，点一下即可（你已登录）。若用 PAT：用户名填 GitHub 账号名，密码粘贴 PAT（需 repo 权限）。
图 3 · push 成功即触发云端构建
本机 POST 实测不稳：带代理被 502 拒，去代理直连时通时断。可试 env -u HTTP_PROXY -u HTTPS_PROXY -u http_proxy -u https_proxy git push -u origin main；仍不行就走 PAT + api.github.com REST，或换机用 bundle。

打开 https://github.com/clearlove6938/goutoujunshi-geren/actions（就是仓库页顶部的 Actions 标签），找到 Platform preview packages 的最新一次运行，等 android job 变绿（要装 Android SDK 35，约 5–15 分钟）。

图 4 · 下载后解压得到 app-debug.apk（Artifacts 需登录 GitHub）
首跑真实失败已修复并二次通过。第一次 android job 报 ./gradlew: Permission denied (exit 126) —— 仓库在 Windows 上初始化，gradlew 被记成 100644 不可执行。已把 workflow 改成 bash gradlew … 并把该文件 mode 补为 100755，重新推送后 android job success。Kotlin 代码本身无编译错误。

排错速查

现象原因 / 处理
error: remote origin already exists.说明你走的是 bundle clone 路径（origin 指向 .bundle）。改用 git remote set-url origin <仓库地址>，或直接用第 3 步那条通用命令。
CONNECT tunnel 502 / Empty reply from server代理只放行 GET，挡 POST 大包。去掉代理直连重试；仍不稳就改走 PAT + api.github.com REST API，或换机用 bundle。
could not read Username网络已到 GitHub，只差认证。让 GCM 弹浏览器授权，或用 PAT 当密码。
生成 PAT 时跳到 Confirm access，红字 Sudo authentication failed.GitHub 的 sudo mode：进 Settings / 生成 PAT 属敏感操作，要二次验身份。红字只说明上一次密码或 2FA 没通过，不是封号、也不是推送失败。点绿色 Verify via email → 绑定邮箱收验证码 → 回来继续生成 PAT；sudo 通过后几小时内不再问。
也可以完全不要 PAT：在自己终端跑一次 push 并点 GCM 的浏览器 OAuth 授权（不触发 sudo），token 会缓存，之后由我走 api.github.com REST 完成上传。
提示输入 GitHub 用户名 / 密码正常。GCM 会弹浏览器授权；用 PAT 时用户名填账号名、密码填 PAT（repo 权限）。
Actions 页面没有运行记录新仓库首次 push 偶尔不触发。点「Run workflow」手动跑，release_tag 留空。
./gradlew: Permission denied / exit 126Windows 初始化的仓库把 gradlew 记成 100644。改 workflow 用 bash gradlew，并把该文件 mode 设为 100755 后重推。本次已修复。
Artifacts 下不了需登录 GitHub 账号；GitHub 对未登录下载 artifact 有限制。
手机提示签名不一致调试签名与旧包不同，卸载重装；先备份配置。
设置页找不到开关装的是官方 Release 包。必须用本教程构建出的 app-debug.apk。

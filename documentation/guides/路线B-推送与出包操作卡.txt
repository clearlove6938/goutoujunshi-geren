【第 3 步：推送】
cd goutoujunshi-jev-chat
git remote add origin https://github.com/clearlove6938/goutoujunshi-geren.git 2>/dev/null || git remote set-url origin https://github.com/clearlove6938/goutoujunshi-geren.git
git remote -v
git push -u origin main
（第一行两条路径都通用：无 origin 就 add，已有就 set-url，不会报 already exists。）

注意：
- 本机仓库无 remote，所以用 remote add 是对的；
  只有「从 bundle clone」出来的仓库才必须 set-url。
- GitHub 页面给的 `git branch -M main` 不需要，本来就是 main。
- 首次 push 弹浏览器授权点一下即可；用 PAT 时用户名填账号名、密码填 PAT。
- 【19:58 实测诊断】`git ls-remote` 通 ≠ `git push` 通：
  带代理 push → CONNECT tunnel failed 502 / Empty reply from server（代理只放行 GET，挡 POST 大包）；
  去代理直连 → 有时能走到「could not read Username」（网络已到 GitHub），有时 21s 超时连不上；
  强制 http.version=HTTP/1.1 无改善。所以本机自动 push 不稳定，且**无论如何仍缺认证**。
- 去掉代理直连的完整命令：
  env -u HTTP_PROXY -u HTTPS_PROXY -u http_proxy -u https_proxy git push -u origin main
- 最确定的路：给一个 repo 权限的 PAT，改走 api.github.com 的 REST Git Data API
  （该域名稳定 200，可完全绕开被挡的 git 端点），一次上传完并触发 Actions。

【可能出问题】
- android job 报 `./gradlew: Permission denied` (exit 126)：已修复，见顶部「已完成」。
  若以后在 Windows 上重新初始化仓库，记得 `git update-index --chmod=+x
  integrations/jev_android/gradlew`，或在 workflow 里用 `bash gradlew`。
- Artifacts 需要登录 GitHub 才能下载。
- 安卓版不支持微信截图；用 QQ / X / 飞书 / Soul 走手动截屏流程。
- error: remote origin already exists → 说明走的是 bundle clone 路径，改用 set-url。
- 生成 PAT 时跳到 "Confirm access" 页、红字 "Sudo authentication failed."：
  这是 GitHub 的 sudo mode（敏感操作二次验身份），不是封号，也不是推送失败。
  红字只表示上一次密码 / 2FA 没通过；点绿色 "Verify via email" → 绑定邮箱收验证码
  → 验证后回到 Settings 继续生成 PAT。sudo 通过后几小时内不再重复询问。
  不想走 sudo：可完全不要 PAT，改在自己终端跑一次 `git push` 并点 GCM 的浏览器授权，
  OAuth token 会缓存到 Windows 凭据管理器（普通授权，不触发 sudo），之后由我用
  api.github.com REST 完成上传；这样 PAT 也不用交给别人。

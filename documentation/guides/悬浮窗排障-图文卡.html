首页全绿、助手已开启，为什么还是没有悬浮球

已定位到代码层原因，并已修好源码。这张卡先让你用 30 秒确认现象，再给手机上立刻能做的动作。

0先说结论

首页那三项（无障碍权限、悬浮窗权限、密钥）只检查「能不能显示」，完全不检查「有没有触发显示」。所以三项全绿和「球没出现」并不矛盾。

真正的开关在下一层：无障碍服务收到窗口事件后，会去读当前聊天窗口的控件树。QQ 属于「已适配应用」，读不出来时旧代码直接 return，既不显示球也不报错——这就成了你现在看到的样子。

为什么偏偏是 QQ：QQ 适配器靠三个写死的控件 ID 认页面（id/mjn 气泡、id/371 标题、id/input 输入框）。新版 QQ、群聊页、以及一加/OPPO 系统对无障碍节点的限制，都可能让这三个 ID 失效。而不适配的普通 App 反而有兜底会显示球，所以这是一个很反直觉的现象。
先做自测，两条分支的处理完全不同，不要跳步

项目改成为什么
会话白名单（每行一个关键词）整框清空只要这里非空，标题读不出来的会话会被判为「不允许」，代码会主动把球隐藏。这是唯一一个用户设置能直接把球关掉的开关。
树读不到正文时用 OCR 兜底打开控件树读不到文字时改走截屏识别，不再空手返回。
悬浮球菜单里的「隐藏助手（本次）」别点点了之后要重进聊天窗口才会重新出现；不确定就按第 2 节重绑一次。
再试一次：进 QQ 单聊（群聊更容易识别失败）→ 按 Home 回桌面 → 再切回 QQ。这一步是为了触发一次新的 TYPE_WINDOW_STATE_CHANGED 事件，服务靠它决定要不要显示球。
只要旧 APK 上球能出来，长按球 →「截屏识别一次」→ 核对原文 → 分析，就能绕开失效的 QQ 控件 ID 完整跑通一轮。识别方式可先用「ML Kit 本地」，不耗接口额度。
如果这几步做完，QQ 里仍然始终没球，那就必须装修复版 APK —— 旧包的 extract() == null → return 是硬伤，设置改不出来。

2别的 App 也没球 → 强制重新绑定服务

一加 / OPPO（ColorOS、OPlus）会把无障碍服务冻结，开关显示「已开启」但服务进程没在收事件。按顺序做：

  1. 系统设置 → 无障碍 → 找到「狗头军师 Jev Chat」（描述是「读取当前聊天窗口文字，用于生成回复建议」）→ 关闭。
  2. 系统设置 → 应用管理 → 狗头军师 Jev Chat → 强制停止。
  3. 回到无障碍 → 重新打开该服务，弹窗确认。
  4. 打开 App，确认首页「助手已开启」仍是开；然后切到任意普通 App，看球是否出现。
还要在应用管理里补两处：电池优化设为「不优化 / 允许后台运行」、自启动允许。悬浮窗权限在系统设置里显示「已允许」后，最好也关一次再开一次，让 canDrawOverlays() 重新返回 true。

顺带修掉的一个隐患：悬浮球坐标以前只校验了 X 上界、没校验 Y 上界。换过横竖屏或分辨率后，保存的位置可能把球画到屏幕外，看起来和「完全没有悬浮窗」一模一样。新包会把超界位置回落到默认值。

5顺带确认：策略失败那次

之前截图里模型名填的是 deepseek-flashsk，末尾多了 sk。客户端会把这个字段原样当作 model 发给接口，服务端不认识就报错，而错误被统一显示成「请检查模型、密钥和网络」，所以看不出是拼写问题。正确值是 deepseek-flash，改完点「测试策略判断」，再保存全部设置。

这一项和悬浮球无关：悬浮球由无障碍服务绘制，不调用任何模型接口，API 没配好也照样应该有球。两件事分开修，不要互相等。

6「悬浮球常驻」开关与保活

常驻开关已做好 常驻版 APK 已出包
最新版 狗头军师-微信截图版.apk（含常驻开关与微信截图实验开关）在「设置 → 外观」最上方保留了 「悬浮球常驻（任何界面都不自动隐藏）」，默认关闭。 打开后桌面、系统界面、本 App 设置页、微信里都不再自动收球；白名单不匹配的会话只跳过分析、不收球。 首页「助手已开启」总开关仍是最高优先级，关掉它球一定会消失。 微信里也会显示球；但能不能真的截微信，由「设置 → 分析 → 允许微信截图」单独控制（实验性、默认关，开启后走系统截屏授权）。

「常驻」要分开看两件事：

现状你要做什么

让保活真正生效（一加 / OPPO 必做）

  1. 应用管理 → 狗头军师 Jev Chat → 耗电管理：允许后台运行 / 关闭「智能省电」；电池优化设为不优化。
  2. 打开自启动，并允许关联启动。
  3. 多任务列表里把 App 卡片下拉锁定（加锁图标），一键清理时别被划掉。

7识别结果把「我」的话全算成「对方」

现在就能解决，不用换包：核对页是可以编辑的。
长按悬浮球 →「截屏识别一次」→ 弹出的「核对本轮对话」文本框可以直接改字。 把属于你发的那几行开头的 对方： 改成 我：， 其余保持 对方：，再点「确认原文并分析」。 全角／半角冒号都认。这一步不是可选的装饰——项目本来就要求人工核对说话人，确认后才会调用分析模型。

为什么会全归「对方」

默认识图方式是 ML Kit 本地 OCR。它拿到的是「一整屏的文字行 + 每行坐标」，没有气泡边框，所以旧版代码在 groupOcrLines() 里把每一组都硬写成 Msg("other", ...)。源码注释和面板提示都直说了：OCR_NOTE = "OCR 未分边，把全部消息当作对方所说"。这不是模型认错，是根本没做分边。

完整因果链：QQ 控件 ID 失效 → 控件树读不到 → 走 OCR 兜底 → 平面读屏判不了左右 → 全部记为对方。所以前面「QQ 里没球」和这个问题是同一条链上的两环。

如果切到了「视觉模型（DeepSeek 等）」，旧版 prompt 只说「格式 我：／对方：」，完全没告诉模型怎么区分左右，模型也只能靠猜；而且解析时只认全角冒号，模型一旦输出 我: xxx 或带 - 前缀，整行会被静默丢掉。

新版改了什么

路径修复
本地 ML Kit 整屏 OCR新增纯函数 ocrLineIsMine()：用每行的左右边缘和屏幕两侧「头像留白」比较，明显贴右且左侧不贴左的行判为「我」。刻意保守——长气泡会横跨大半屏，宁可仍归「对方」让你手动改，也绝不把对方的话错当成自己说的。每组只用最上面一行判方向。
视觉模型prompt 明确写死「靠右／头像在右＝我，靠左＝对方，群聊里除我之外一律对方，分不清就写对方」，并要求忽略时间戳、昵称、输入框、已读回执。
解析与核对页兼容半角冒号和 markdown 列表符号，不再静默丢行；核对页提示改成直说「把你发的每行改成我：」。OCR_NOTE 同步更新。
建议继续用 「ML Kit 本地」：离线、不耗接口额度、中文识别稳，配好核对页就够了。选视觉模型的话，要确认那个模型真的支持图片输入，否则只会拿到一段凭空猜的文字。
说话人判错会连带影响分析：latest_from、自动分析触发、候选回复的口吻样本都按「谁最后发言」算。所以核对页这步别跳过，改完再确认。

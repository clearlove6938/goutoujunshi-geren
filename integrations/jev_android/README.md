# 狗头军师 Jev Chat · Android 源码适配

本目录基于 [Jev Android](https://github.com/jev-chat/jev-chat-jarvis) 的聊天应用采集、ML Kit 中文离线 OCR、悬浮窗、Jev 判断和候选填入链路。已改为独立应用 ID `com.goutoujunshi.chat`，接入狗头军师的自然口吻、事实与推测边界、下一步和停止条件。原文与说话人仍需用户核对；程序检查可见对话里对方最后一条消息中的部分停止联系表述，自己的后续回复不会解除拦截。不可见的历史和未匹配的表述仍需用户核对。程序不自动发送。

**状态：提供 Android 11+ 调试预览 APK，真机验收尚未完成。** 本分支新增**实验性、默认关闭**的「允许微信截图」开关：开启后微信走用户授权的系统截屏 + 整屏本地 OCR，不读控件树、不后台自动采集；支付 / 收款码等受保护页面仍拿不到画面，详见 [完整使用教程 4.8](../../documentation/guides/完整使用教程.md)。QQ、X、飞书等聊天应用路径仍需在对应设备上验证。首次安装后的助手和自动分析默认关闭，需在界面中主动开启。本目录不包含上游现成 APK。

设置页可选择 Jev 或 DeepSeek 官方进行策略判断，回复模型可配 DeepSeek、OpenRouter 等兼容接口；两者分开配置。视觉接口可选择 DeepSeek Flash、OpenRouter、通义兼容或自定义模型，截图识别开关可在本地 ML Kit 与视觉模型之间切换。云端识图会发送聊天区域截图并产生服务用量。识别后的对话须核对原文和说话人，再由用户确认分析；结果包含意图、策略、相对排序、「详细分析」和「更像我一点」。关系联系人可保存阶段、目标和补充背景；K 线窗口可查看五种示例走势或导入带 `timestamp,sender,message` 的聊天 CSV。K 线展示消息方向净差，不能解释为关系质量或成功率。

## 截屏方式配置（0.1.8-preview）

在「设置 → 分析 → 手动截屏方式」选择取图方式，点击「保存全部设置」。悬浮球长按菜单统一保留「截屏识别一次」，也可点击面板的「分析当前对话」手动读取未专门适配的应用。两者都使用保存的截屏方式；已移除独立的系统截屏入口及图片导入功能。

- **无障碍截屏（默认）：** 使用已开启的无障碍服务，不会每次弹出截屏授权。部分模拟器会成功返回图片，但像素全部为黑色；程序会识别黑图并提示到设置中改选系统截屏。
- **系统截屏：** 每次操作会显示 Android 授权弹窗，点击「立即开始」后返回原聊天。取得一张有效画面后立即停止投射服务；不录音、不保存授权。保存这项设置仅保存所选方式，不能省去下一轮 Android 的授权确认。
- **识图模型独立配置：** ML Kit 在本机识别，视觉模型会把截图发送至已配置的服务。识别后仍需核对原文与「我／对方」，确认后才进行策略分析。
- **自动 OCR 保持无障碍路径：** 不会因为选择了系统截屏，就在后台自动打开授权弹窗。系统截屏仅由用户手动触发。
- 授权取消、会话变化、持续全黑或系统投射存在大面积全黑边缘时，恢复悬浮窗并给出提示，可进入「设置截屏方式」或「重试截屏」。不完整的投射图片不会进入 OCR。授权期间请保留原聊天内容，不要切换对象或滚动记录。

本轮在 MuMu Android 12 中复现了无障碍截屏全黑及系统投射裁切。竖屏下曾成功取得完整投射画面，识别出双方 16 条消息并进入原文核对页；多轮测试仍出现过黑图或裁切，不能认为模拟器截屏已稳定修复。42 项单元测试与调试 APK 构建通过。其他设备及 Android 14+ 仍需实机验证。

上面的历史说明针对 `v0.1.8-preview`：那一版确实没有微信路径，也无法让受系统保护的黑屏内容变成可读图片。本分支后来加了「允许微信截图」开关，做法不是修好无障碍截图，而是**绕开它走系统截屏授权**；FLAG_SECURE 页面依然拿不到画面。

## 2026-11-06：实验性微信截图开关（本分支）

- 上游把微信挡在 4 处：窗口事件 drop、`ocrCaptureManual()` 的 toast、未适配 App 的补球排除、`WeChatAdapter` 未注册。本分支把前 3 处改为由 `Prefs.wechatCaptureEnabled` 控制，**默认关**。
- 微信不注册自动读控件树（8.0.52+ 会隐藏节点文字）；只保留长按悬浮球 →「截屏识别一次」的整屏截图路径，且**固定走 `Prefs.CAPTURE_SYSTEM`**（MediaProjection 用户授权）。`externalCapture()` 放宽了 root 为空的限制，避免微信不给节点树时静默失败。
- 设置 → 分析 →「允许微信截图（实验性）」；首页与常驻开关说明同步更新。核对页仍是说话人归属的唯一权威。
- 隐私：识图方式建议保持 ML Kit 本地；选云端视觉模型会把微信聊天截图外发，见 [PRIVACY.md](../../PRIVACY.md)。

## 2026-10-06：安卓流程与 DeepSeek 修复

- **核对与取消：** 隐藏助手、关闭总开关或切换会话会清掉旧核对状态，取消等待焦点、后台任务和过期显示回调。HTTP 连接会尝试断开，后续请求不会继续；已经发给服务的请求无法撤回。
- **DeepSeek 上下文：** 判断、标签轮换、候选排序、详情和回复解释使用当前联系人关系、阶段、目标、背景和选定历史；联系人关系优先于全局默认关系。
- **候选校验：** 只接受最多三条、每条最多四十字的完整 JSON 字符串数组。错误说明、对象、数字和截断输出不会成为填入内容；显示错误后可重试。
- **会话与建议：** 不同标题的会话分别去重，补齐七种中文策略建议。对方要求停止联系后，即使自己又发了消息，也保持候选拦截；对方再次主动发消息后按新一轮判断。
- **OCR 与配置：** OCR 自动分析开关进入实际流程；策略测试读取当前表单的回复地址和密钥，无需先保存。跨服务密钥仍不共用。
- **回归测试：** 新增核对状态取消、旧结果失效、HTTP 请求取消、候选格式、联系人上下文、会话身份和明确边界测试。

## 安装与配置

从[最新 Release](https://github.com/shengjidaguai-china/goutoujunshi-jev-chat/releases/latest)下载 `goutoujunshi-jev-chat-android-debug.apk`，在 Android 11 或更新版本上允许系统安装此来源的应用后安装。旧版调试 APK 与新版可能由不同的临时调试证书签名；如提示签名不一致，需卸载旧包再安装，本机应用数据会随卸载清除，先记录好需要保留的设置。打开应用，配置判断和回复接口，按提示授予无障碍、悬浮窗权限，再主动开启助手。应用只生成草稿，由你决定是否发送。请勿使用该版本尝试读取微信聊天。

「策略判断」集中配置判断来源和接口：选择 Jev 时，显示 OpenRouter／TypeSafe／自定义渠道以及地址、模型和密钥；选择「DeepSeek 官方」时，显示其官方地址、模型和密钥。页面只显示当前来源的配置，切换来源会保留已填写内容，原有保存设置继续适用。「测试策略判断」测试当前选中的来源。

只用 DeepSeek 判断和回复时，在「策略判断」选择「DeepSeek 官方」，在「回复接口」也选择「DeepSeek 官方」，填写模型和密钥后保存全部设置。策略密钥可以单独填写；回复接口指向 DeepSeek 官方时，策略密钥留空可复用回复密钥。测试读取当前表单，因此刚填完也可以测试，正式使用前仍需保存。识图方式独立选择本地 ML Kit 或视觉模型。

## 可选：使用完整狗头军师 Skill

APK 内置了一份未经修改的上游狗头军师 Skill（`app/src/main/assets/goutou_skill/`，含 `SKILL.md`、20 份知识文档与 23 份实用指南，MIT）。设置页的「使用完整狗头军师 Skill」默认**关闭**：关闭时只用 `GoutouGuidance.draftRules` 的精简规则；开启后，每轮候选生成和详细分析会额外注入 Skill 核心章节，以及按联系人「目标」选取的 2–3 份场景指南。

- 场景取自知识库里联系人的目标：自然接话 / 主动邀约 / 澄清关系 / 修复冲突 / 减少投入 / 结束联系；没有匹配联系人时按「自然接话」处理。
- 注入上限 6000 字，按整行截断；首轮问卷、长期记忆等桌面外章节不会进入手机端 prompt。
- **Jev 的判断题不变**：`JevQuestions` 的英文题面经过校准，只增强回复生成层，不往判定层塞中文规则。
- 开启会明显增加每轮输入 token 与费用；不需要时关掉即可，设置即时生效，不改动任何已有数据。
- 上游 Skill 原文写有「不写用户工作区 / 数据不外发 / 不发起网络请求」，那描述的是本地 Codex Skill 自身；注入前会追加「移动端运行时适配」声明，说明截图识别与模型调用由 App 完成，且 JSON 输出契约优先。

资源由仓库根目录脚本生成，同步上游新版本时重跑：

```bash
python -B scripts/sync_android_skill.py
```

离线校验（不需要 Android SDK）：

```bash
python -B -m unittest tests.test_android_skill_assets -v
```

## 手动识别一轮对话

QQ、X、飞书有专门的采集适配；Soul 等其他应用使用手动截图入口：

1. 开启助手后，打开目标聊天应用，保持要分析的对话可见。
2. 长按「军师」悬浮球，选择「截屏识别一次」。0.1.8-preview按设置中的「手动截屏方式」执行；选择系统截屏时需确认 Android 弹窗。
3. 在核对页修改识别原文与双方归属，每行使用「我：」或「对方：」开头。
4. 点「确认原文并分析」，等待原聊天应用焦点恢复，再查看判断与候选。
5. 复制候选，或点击「填入」。未专门适配的应用无法验证输入框，会退回复制；已有草稿也会保留。发送始终由你手动完成。

## OCR 自动识别与手动入口

「OCR 模式自动分析」关闭时，专门适配应用的自动 OCR 识别完只显示悬浮球；点击「分析当前对话」才打开原文核对页。开启后，最新消息来自对方时自动打开核对页。所有模型分析仍需用户点击确认。

长按悬浮球选择「截屏识别一次」属于主动操作，不受自动开关限制，识别后直接打开核对页。本地全屏 OCR 默认把消息标为对方，需要手动纠正双方归属；视觉模型识别也需要核对。

## 仍需实机验证的范围

- Android 版仍不支持微信；QQ、X、飞书和其他应用的截图、焦点及输入框行为需要对应设备验证。
- 通用 OCR 应用无法验证输入框，会退回复制；相同标题、无法读取标题的会话仍需要用户核对当前对象。
- 云端视觉和策略模型的接口能力、费用、实际输出与 token 权重支持情况由所选服务决定，本轮使用离线响应和自动测试验证逻辑。
- 调试 APK 使用临时签名，旧包可能不能直接覆盖安装。真机安装与权限授予仍需用户验收。
- 当前停止联系拦截依据可见对话中对方最后一条消息及有限表述，不能替代完整历史和人工判断。

## 从源码构建

要求 Android 11+，构建机须安装 JDK 17、Android SDK 35。进入本目录后运行：

```bash
./gradlew :app:testDebugUnitTest :app:assembleDebug
```

成功后调试包在 `app/build/outputs/apk/debug/`。应用的设置页可分别配置判断、回复、视觉接口；只有同一协议、主机和端口的接口才能共用密钥，跨服务须分别填写。请仅在自己的设备和有权查看的对话中使用。数据使用见仓库根目录 [说明](../../PRIVACY.md)。

把改动推到 fork 后，`.github/workflows/platform-build.yml` 的 android job 会跑同一条命令，在 Actions 的 Artifacts 里给出 `goutoujunshi-jev-chat-android-debug`；本机不需要装 Android SDK。内置 Skill 资源由 `scripts/sync_android_skill.py` 生成，改动 `skills/` 或 `integrations/jev_android/` 都会触发构建。

源码来源与署名见本目录的 [LICENSE](LICENSE) 和 [NOTICE](NOTICE)。
